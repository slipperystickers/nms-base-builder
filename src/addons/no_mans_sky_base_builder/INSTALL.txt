BASE BUILDER EXTENDED 18.2.46
Base Builder by DjMonkey; Extended by Furiousfurby.
Based on Kuma's 18.0.0 release.

REQUIREMENTS
64-bit Windows, Blender 5.1 or 5.2. This release was tested with 5.1.2.
The station reference library was saved with Blender 5.1. This combined build
does not claim the Blender 4.2 compatibility of Kuma's original ZIP.
Simple proxies, icons, game lighting and Python dependency wheels are included.
Detailed proxies use a separate, optional HD library, installed once from inside
BBE. No additional plug-in, NMSDK, external Python or pip command is required.

HIDDEN VANILLA STATION PARTS
The Asset Browser includes a separate Vanilla Hidden Station Parts category.
These entries have current native game ObjectIDs and models but are omitted from
the normal in-game construction menu. GAMETABLE is available under Interior as
the Holo-Arena Game Table. Its visible placement is supported; interactive game
setup is not claimed and still needs an in-game test.

INSTALL / UPDATE
1. Save your Blender work. Keep this ZIP intact.
2. Edit > Preferences > Get Extensions > top-right menu > Install from Disk.
3. Select the ZIP and enable Base Builder Extended.
4. Restart all Blender windows after upgrading.
Existing Detailed Proxy users do NOT need a fresh install or manual pack download.
With Blender Online Access enabled, BBE checks the installed packs automatically
and downloads only missing or changed components. Keep Blender open until the HD
progress finishes. Verified detailed scenes refresh automatically; Simple scenes
stay Simple. The previous compatible pack remains available during the download.
If a download fails, open Detailed Proxies and choose Retry Download. Offline
users can enable Online Access later or install the matching verified pack ZIP.
New users can opt in through Builder > Detailed Proxies.
If Charon Forge is enabled, BBE asks before activation. Continue disables
Charon Forge and enables BBE; Cancel leaves Charon active and BBE inactive.
BBE cannot intercept Charon's own installer. If Charon is enabled later,
BBE warns that the session is incompatible; save work, close Blender, and
restart with only one of the two add-ons enabled.
For existing low-resolution curved bubble ducts, use Builder > Detailed Proxies.
New pipes and bubble ducts added from the Asset Browser automatically join an
endpoint of the selected pipe or bubble duct. Use Snap controls to cycle ends.
For habs or the Thunderbird bay already placed in an older saved scene, select
those parts and switch to Low-Res, then back to High-Res to refresh their meshes.
This replaces the installed extension with the same ID; do not enable duplicate
copies of Base Builder at the same time. Keep your previous ZIP for rollback.

STATION WORKFLOW
In Save Manager, enable the save controls, choose your account and save slot,
click Station, choose your station, then Import from Save.
Space remains available for orbital space bases, separately from stations.

Import from Clipboard and I/O > Import Build from File also load the station reference
automatically when the JSON includes BaseType.PersistentBaseTypes set to
PlayerSpaceStationBase. Copy the complete station base record from the editor.
Objects-only lists do not identify the base type and import only the parts;
use Save Manager or the complete station base JSON to get the reference.

STANDALONE BUILD FILES
Use I/O > Import Build from File for .nmsship, .nmsbase, .nmsprefab and build
JSON/TXT. Export Corvette .nmsship or base .nmsbase from the relevant Save
Manager tab. These are local files; Export to Save writes to the selected game
save and creates a backup first. Save/Open Project JSON stores a BBE project,
not a NomNom or optimizer build file. For a new .nmsship, choose an existing
ship package as the metadata template when exporting.

Station Player Parts contains the editable build. Station Reference contains
Outside and Inside. Outside has all six hull families and the major optional
parts. Use the Outliner triangles to expand and the eyes to show/hide them.
Keep one hull body and compatible attachments visible. See
resources/station/Station exterior choices.md for the combinations.
Inside has separate floors/fixtures, roof, and wall cutaways.
For Save Manager imports, reference controls appear in the Station tab.
For clipboard/JSON station imports, expand Station Reference under Import/Export.
These controls do not require Save Manager to be enabled or a save to be selected.

Click Remember Station Visibility to reuse that station's eye settings.
For an older station scene, Refresh Reference Library replaces the reference
and preserves player parts and visibility. Save the blend afterwards to retain
the smaller reference. Imports/refreshes compact the collection lists once;
opening a saved blend retains its saved layout.

The exterior is matched manually. The saved procedural station seed has not
been decoded. The reference does not alter the in-game station.

PLACEMENT
With no active object selected, adding a part uses its normal origin, rotation
and scale. With an active object selected, the part inherits that transform.
This applies to both the native Asset Browser and legacy/proxy add paths.

DETAILED PROXIES
Use Builder > Detailed Proxies. Installed models are detected automatically.
If they are missing, confirm Download & Enable. Blender downloads, verifies and
installs the complete pack, then turns Detailed Proxies on automatically. No
manual ZIP extraction or restart is needed. Progress and Cancel Download appear
in the Builder menu and temporarily in the sidebar. All models install together;
individual parts never trigger downloads or game-file conversion.
The installed pack is shared across Blender versions and survives normal BBE
updates. HD browser icons are always included with the main add-on.
For offline installation only, use F3 > Install Detailed Proxies from ZIP
(Offline). This also installs and enables a verified pack automatically.

GAME LIGHTING & SCENES
Open Game Lighting & Scenes in the Base Builder sidebar. Turn on Game Lighting,
choose Planet or Space, then choose a sky. Planet offers biome/weather and time
of day; Space offers nebula, galaxy, starfield and deep-space styles. Use Advanced
for exposure, sunlight, sky brightness and lamp strength. Lamps creates Blender
lights from supported parts' game data; Refresh Lamps after adding/removing parts.
Lighting presets are stored in ~/NoMansSkyBaseBuilder/lighting_presets.
Turning lighting off restores the previous world, colour management and viewport
shading. The settings and generated lamps are scene-specific and are not exported
to No Man's Sky. They approximate the game's renderer, not an exact simulation.

SHARING
Send the main ZIP; the optional bbe-hd-library-1.zip can also be shared for offline
installation. Recipients use their own saves. Personal saves, test scenes,
appearance profiles and research tools are not included.

AUTOMATIC UPDATE CHECKS
On first use, choose Yes in Enable auto updates? to allow Blender internet
access and automatic update checks. No or dismissing the prompt keeps checks
off and remembers your choice. Change it later in Updates & Support.
Updates are installed when you choose; downloads remain verified installer ZIPs.

WASD NAVIGATION (OPTIONAL)
Toggle WASD Navigation in either the top BBE menu or the BBE sidebar.
In Object or Mesh Edit mode, hold right mouse and use WASD or arrows to move.
Q/E moves down/up, Shift speeds up, Ctrl slows down, wheel changes speed.
Release right mouse or Esc stops. Quick right-click opens the context menu.
Requires Blender left-click selection. Moves only the viewport, never camera objects.

SHIP WARNINGS AND REPAIR
The I/O Corvette selector shows affected builds in red as soon as the save loads.
Select a warning entry to see its explanation and Repair - Keep My Build button.
Repair keeps the saved parts and their transforms/colors, plus readable ship
inventories, technology, hyperslots, class, stats and appearance. Any unreadable
data resets are listed and require a separate confirmation. Backups precede writes.
Slots use numbers 1-12; the freighter is listed separately. Missing-build Corvette
slots also appear in the selector. An invalid slot link requires explicit review
in Ship Management rather than guessing a destination.
Red Ship Management rows explain slot/build mismatches. Link Status has details.
Repair Build stages the same keep-build repair inside Ship Management.
Replace From File is separate: review a complete .nmsship replacement, or replace
only build objects on a correctly linked Corvette. Duplicate builds require explicit
confirmation. Save Changes creates verified backups before writing the reviewed
draft. Unrelated ships and freighter data are preserved. Structural checks do not
guarantee in-game functionality.

COCKPIT ORDER AND FEATURE HELP
Swap Cockpit/Object order is in Builder (top toolbar and sidebar) and Optimizer Settings.
Choose Cockpits, an appearance modifier type, or any other duplicate Object ID, then choose two instances.
Choose any two cockpits and confirm. This immediately exchanges their export order;
it never moves their models. Both ordinary and optimized exports use this order.
Save the .blend to retain it with that project. Ctrl+Z undoes the scene change;
opening another project uses that project's own order. The game save changes only
when you export. Canceling Optimizer Settings does not undo a confirmed scene swap.
Hover over controls for a short explanation. How this works and BBE Feature Help
provide local information boxes about effects, timing, preservation and recovery.

EXPORT TO AN EXISTING SHIP OR A NEW SLOT
Corvette Export to Save and Optimize & Export offer Overwrite Selected Ship or
New Empty Ship Slot. New slots use a minimal Corvette ship record and exactly
the scene objects. No template parts are inserted. Existing destinations retain
readable ship data; any data resets require review. A slot with an orphan build
is not considered empty. Main and Expedition destinations are listed separately.
Repair and export never insert a missing cockpit: they warn that the ship will
be unflyable, but allow the operation. Add a cockpit yourself when ready to fly it.

EXPORTING A CORVETTE IMPORTED FROM SAVE
New imports retain the original ship's inventory, class and appearance for Export
Corvette (.nmsship). That source information is saved with the Blender project.
For an older project with existing edits, select its original Corvette in I/O,
then check Use selected save Corvette in the export file dialog. This keeps the
current Blender parts and uses that explicitly selected ship's metadata. A full
.nmsship template is still available for projects without saved ship metadata.
